## Architecture

**Swipe & Bite** is a meal-discovery app (swipe right/left to match with meals). Built with TanStack Start (SSR + server functions), deployed to Cloudflare Workers.

### Routing

File-based routing via TanStack Router. Route files live in `src/routes/`. **`src/routeTree.gen.ts` is auto-generated — never edit it manually.**

Route layout:
- `/` — landing page
- `/auth` — sign in / sign up
- `/app` — authenticated shell (layout guard in `src/routes/app.tsx`)
  - `/app/onboarding` — first-time dietary preferences
  - `/app/mode` — cook vs. takeout selection
  - `/app/swipe` — swipe deck (takes `?mode=cook`)
  - `/app/matches` — saved matches grid
  - `/app/match/:id` — meal detail
  - `/app/ate` — eat log + daily nutrition summary
  - `/app/settings` — profile & preferences

The `/app` layout (`src/routes/app.tsx`) handles auth guard and redirects unauthenticated users to `/auth`.

### Server Functions

TanStack Start server functions (`createServerFn`) live in `src/lib/*.functions.ts`. All protected functions compose the `requireSupabaseAuth` middleware from `src/integrations/supabase/auth-middleware.ts`, which validates the Bearer token and injects `{ supabase, userId, claims }` into context.

Key server functions:
- `enrichMealRecipe` (`src/lib/recipe.functions.ts`) — Tavily Search → Firecrawl scrape → Gemini AI parse, with permanent per-meal caching in the `recipes` table
- `estimateMealNutrition` / `searchGroceryStores` (`src/lib/match.functions.ts`) — AI nutrition estimation cached on `meals.nutrition`; grocery store search via Tavily

### Supabase

- **Browser client**: `src/integrations/supabase/client.ts` — import as `import { supabase } from "@/integrations/supabase/client"`
- **Server admin client**: `src/integrations/supabase/client.server.ts` — service-role key, only importable from server functions
- **Generated types**: `src/integrations/supabase/types.ts`
- `auth-middleware.ts` and `client.ts` are auto-generated by Lovable — avoid hand-editing them

Auth state on the client is managed by the `useAuth` hook (`src/hooks/use-auth.ts`), which subscribes to `supabase.auth.onAuthStateChange`.

### AI Gateway

All AI calls go through `https://ai.gateway.lovable.dev/v1/chat/completions` using `LOVABLE_API_KEY`, targeting `google/gemini-2.5-flash` via OpenAI-compatible tool-calling format.

### Vite / Build

`vite.config.ts` wraps `@lovable.dev/vite-tanstack-config`. **Do not add** `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, or `cloudflare` plugins manually — the wrapper already includes them and duplicates will break the build.

The `@` path alias resolves to `src/`.

### Accessibility

`src/lib/a11y.ts` manages color-blind mode and reduced motion. Settings are stored in `localStorage` and applied as CSS classes on `<html>`. The root component listens to a custom `sb:a11y` event to sync state across tabs.

## Environment Variables

```
SUPABASE_URL
SUPABASE_PUBLISHABLE_KEY
SUPABASE_SERVICE_ROLE_KEY
LOVABLE_API_KEY
TAVILY_API_KEY
FIRECRAWL_API_KEY
```

Server functions read these from `process.env`. The Vite client injects `VITE_*` prefixed vars automatically.

## Database

Supabase PostgreSQL. Schema is managed via migration files in `supabase/migrations/`. Key tables: `meals`, `swipes`, `matches`, `pins`, `recipes`, `profiles`, `preferences`, `user_roles`, `contact_messages`. Supabase Auth triggers auto-create `profiles`, `preferences`, and `user_roles` rows on signup.
